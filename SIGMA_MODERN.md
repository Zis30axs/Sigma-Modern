# SigmaModern

Select **SigmaModern** on the mode selection screen. The mode is saved as `SIGMA_MODERN` and shares the existing module registry and settings with the other presentations.

The supplied `Jello-Modern.html` started out as the visual reference (a pale translucent workspace card, blue-grey text, fine borders, rounded corners, a blurred scene backdrop). It is now treated as mood reference only: SigmaModern is designed around its own cold ice / snow / glass / Σ identity, and anything in the HTML that only made sense in a ~1500px browser viewport has been replaced rather than ported.

## Main menu

`ModernMainMenuScreen` is a painted winter night with no bitmap background:

- **Scene** (`ModernScene`, shared with the ClickGUI when there's no world): a gradient night sky with twinkling stars, a moon with a soft halo, an occasional shooting star, two slowly drifting aurora ribbons, two low-poly mountain ranges (each apex splits a lit face from a shadowed one, with jagged two-tone snowcaps) and a snowfield of drifts with flat three-tier pines. Skia paints every layer into a texture once per window size - never per frame - each a little wider than the screen, so the layers can slide apart for mouse parallax. Rasters are capped at 4096×2048 and upscaled past that, and each layer paints a bleed band below the screen so vertical parallax never uncovers the sky behind the snowfield.
- **Resizing**: painting the layers takes 0.4–0.8 s at typical sizes, so it runs on a background thread (`SigmaModern scene painter`). Only texture registration happens on the render thread. Until a new size's layers are ready, the previous ones are drawn zoomed uniformly to cover it, anchored at the bottom centre, so nothing is squashed. The new set then crossfades in over 0.35 s. The very first set fades in over the bare sky. On the render thread this took a maximize to a ~1 s frozen frame, which Windows showed as the old frame stretched. Measured with `-Dsigma.debug.maximizeAfterFrames` (see Verification): restore went from 469 ms to 26 ms. The first maximize still costs ~180 ms once, for GPU allocations at the new size, and none after that.
- **Snow** (`ModernSnow`): a fixed pool of flakes, sized to the screen area, with nothing allocated per frame. Each flake's depth drives its size, fall speed, opacity and parallax; about one in eight near flakes is a slowly spinning six-armed crystal instead of a soft dot. Mouse motion adds a gentle gust.
- **Hero**: a faceted "ice crystal" Σ (a vector path split into triangles at different opacities, so it reads as translucent ice over the sky) with a breathing halo, the wordmark "Sigma" in Anthropic Serif's display cut with *Modern* in its italic, an eyebrow and a tagline. A serif clock and date sit top right.
- **Destinations**: Singleplayer and Multiplayer are flat serif rows. On hover a band glows, the text slides, an underline grows and an arrow slides in. These rows are real `Button` widgets, so Tab, Enter and narration work; multiplayer is dimmed with its usual tooltip when unavailable.
- **Dock**: Settings / Accounts / Modes / Quit sit in a glass dock that stays tucked below the bottom edge with only a grip and a "MENU" hint showing. It rises when the pointer comes within ~46 GUI px of the bottom, stays up while the pointer is over it, and always rises while one of its buttons has keyboard focus, so Tab never lands on a hidden button. It ignores the last few pixels, which are the window's resize border where GLFW stops reporting motion, and it drops when the cursor leaves the window (`GLFW_HOVERED`). The buttons' real Y is moved every frame, so clicks land where the dock is drawn. Icons are vector glyphs (`ModernIcons`).
- **Motion**: opening fades up from the night-sky color while each element arrives in turn. Choosing a destination fades back out before navigating; the navigation runs from `tick()`, never mid-render. `ModernTransitions` then fades the next screen in from the same color, even when it's a vanilla screen, with its clock starting on that screen's first rendered frame. Returning from a sub-screen gets a short fade rather than replaying the entrance, a resize changes nothing, and a destination that declines to open (e.g. multiplayer becoming unavailable) fades back in in place.
- **Compact layout** (height < 300 GUI px): the eyebrow, tagline, clock and row subtitles drop out.

`ModernStyle.alphaScope` is what makes all the fading cheap. It's a scoped alpha multiplier that every Modern primitive honors (`rounded`, `fill`, text, icons, snow), so a whole group - a card, a menu row, the dock - fades by wrapping it, with no alpha parameter threaded through each draw call.

## ClickGUI

`ModernClickGuiScreen` is a single frosted card: a header, a left category sidebar, a content pane (module rows or the module-detail drill-in) and a footer. A `/`-triggered search view replaces the sidebar with a full-width filtered row list across every category. Esc pops DETAIL/SEARCH back to CATEGORY; Right Shift always closes. The card's height animates to fit its current content up to the available window space, scrolling past that. On opening, the card rises into place as it fades in. Switching category or view cross-fades the content pane. With no world loaded it sits on the same painted night as the main menu - blurred, because the scene ends its own GUI stratum before the blur boundary, while the snow drawn afterwards stays sharp in front.

The category list is a vertical sidebar rather than the reference HTML's horizontal tab bar. That bar fit its ~1500px browser viewport. Ported literally to a Minecraft window at typical GUI scale, it left too little width for nine category names, which then overlapped or were cut to a couple of characters each. A sidebar's width doesn't depend on category count or label length, and most Minecraft ClickGUIs already use that layout. Sidebar rows shrink from 30 to at most 20 GUI px, so all nine categories fit in the tallest card the window allows. Otherwise the last categories get clipped, and become unclickable, at ordinary window heights.

The ClickGUI palette follows the ice-blue identity (`ModernStyle.ICE`/`GLOW`) rather than the reference's neutral workspace grays. Headers use a glowing accent bar plus wide-tracked capitals (`ModernStyle.spaced`). The sidebar's selected category is a soft glow plus a left accent bar - the same "selected/active" language as an enabled module row. A faint faceted Σ sits in the card's corner.

Each sidebar category has an icon to the left of its name, tinted like the name (active or muted): 24×24 line drawings with a 2 px round stroke, one SVG file per category in `assets/minecraft/sigma/icons/category/` - crossed swords (Combat), a double chevron (Movement), a person (Player), a crate (Item), mountains under a sun (World), an eye (Render), a paneled window (Interface), a bug (Exploit) and four tiles (Misc). `ModernSvg` draws SVG files through Skija's own SVG renderer: like `ModernIcons`, each file is rasterized once per device size, so it stays crisp at any GUI scale. A mask keeps only the shape and is tinted by the caller (the icons are drawn white for that); a picture keeps the file's own colours (the flags). A file gives only a `viewBox` and is scaled to fill the box it's drawn in.

### Module tiles

A category's modules (and the search results) are control-centre tiles rather than full-width rows: 46 px tall, as many columns as fit at least 170 px wide (two beside the sidebar, three in the full-width search). The whole tile is the module's switch. On, it turns ice blue with a soft glow and a sheen, and the colours ease between the two states. Its second line says what it's set to: the module's first choice while it's on ("Ambient", "One Seven"), "On" for a module without one, and "Off" otherwise ("Press a key…" while binding it). A bound key shows as a small chip. The › at its top right, or a right-click anywhere on it, opens the module's page, and a middle-click binds it. Descriptions are off the tiles: hovering one turns the footer into its info line ("LowFire · Shrinks the fire overlay…") in place of the enabled count and hints, so reading about a module costs no space in the list. Two-column rows with name, description and switch each felt cramped, and full-width rows left most of each row empty; tiles carry only what you need to scan.

### Module page

A module's page (a click on a row's ›, or a right-click on the row) is a compact inspector rather than a list of full-width rows. The header holds the module's name (1.25×, not 1.6×), its description on one line, its switch, and its keybind as a chip beside the switch: "Bind R · Toggle", or "Not bound · click to bind". Clicking the chip binds, and right-clicking it switches between toggle and hold. Each setting is one 30 px row: name, and description in one small line, on the left; one control in a column on the right, up to 212 px wide and never more than half the row.

- **Switch**: a small toggle.
- **Number**: a short slider (ticks when there are at most 12 steps) with the value in a pill. Click the pill to type a value (a decimal comma works; Enter sets it, clamped to the range; Esc or text that isn't a number leaves it).
- **Choice**: with up to four options that fit side by side, a segmented control where every option is one click and the highlight slides. Otherwise it is a field showing the current option; clicking it (or anywhere on the row) opens a grid of every option under the row, three columns wide, and one click picks. The card grows to fit the grid, and a click elsewhere or Esc closes it. Option names read as words ("One Seven" for `ONE_SEVEN`, via `EnumSetting.label`) unless the enum names itself with its own `toString()`.
- **Colour**: quick swatches, and the value as hex in a pill with the current colour; click the pill to type a hex value.
- **Text**: a field; click to type.

The scroll wheel over a control steps it: a number by its step, a choice to the next or previous option. Anywhere else, the wheel scrolls the page. Hovering a setting that isn't at its default shows a reset arrow beside its control, and clicking it resets the setting.

### Language

A globe button beside the search button opens the **Language** page (and closes it again; so does Esc). It lists the client languages - English, 简体中文, 日本語, 한국어, Русский, Español - one row each with its flag, its name in itself and, under that, its name in the language being shown; the one in use is lit like an enabled module, with a check. A click switches at once and is saved with the config (`"language": "<code>"`). This is the client's own text only; the game's keeps following the game's language setting.

`jello.lang.Translations` looks a key up in the picked language's file, then in English, then shows the key itself. `jello.lang.ClientLanguage` lists the languages, each with `assets/minecraft/sigma/lang/<code>.json` (a flat object of key to text) and a flag, `assets/minecraft/sigma/flags/<country>.svg`. The flags are drawn 3:2 on a 30×20 grid: China on its official construction grid, Korea's taegeuk and trigrams to the official proportions, the US with all 50 stars, and Spain as the civil flag without the coat of arms, which is a blur at 24×16. English is the source. The other five files hold every key with the English text as a placeholder, so translating one is editing its values; a key a file leaves out also reads as English, and `LanguageFilesTest` fails on a key English doesn't have (renamed or mistyped). Adding a language is an enum constant, a JSON file and a flag. So far the ClickGUI's own chrome (category names, header labels, counts, hints, messages) and the TabGUI's category names read their text this way (`ModernText.tr`); the rest of SigmaModern still uses the older two-language `ModernText.t`, which follows the game's language, and module names, descriptions and settings are not keyed yet.

In a world (and only then, since without a player it would just read N), a compass tape runs under the window caption: world bearings scrolled by the player's heading, with ticks every 5°, numbers every 15° and letters at the 45s, fading toward its ends over a dark translucent backing. An earlier version drew labels at fixed screen offsets and only printed a letter when the heading was within 4° of a multiple of 15, so N/E/S/W almost never appeared.

The reference page's simulated music player is now a real NetEase player (see "Music player"); its demo gameplay is not implemented as a game feature (see "In-game HUD").

Earlier passes at these screens were replaced outright and are not recoverable from git (they were untracked):
- An initial port by a different agent reused the older Jello-style masonry ClickGUI and never forced real background blur.
- A first rewrite matched the reference's horizontal tab bar literally.
- An earlier main menu blitted the generated `card.png` artwork behind glass destination cards.

## Window chrome

On 64-bit Windows, while a screen is open the content extends into the original title bar (`ModernWindowFrame`).

- **Caption strip**: `CAPTION_H` = 22 GUI px. It carries a soft top scrim, the current window title with a Σ mark on the left, and minimize / maximize-restore / close on the right (`BUTTON_W` = 34 GUI px each). The icons are anti-aliased vector glyphs. Each button's hover background fades in, and close turns red.
- **Click-through**: the rest of the strip drags the window (`HTCAPTION`) except where the open screen has a widget under the cursor (`Screen.getChildAt`), which stays `HTCLIENT`. Vanilla screens such as Create World and Statistics put tab bars at y = 0, and without this the caption swallowed their clicks.
- **Shared geometry**: `WM_NCHITTEST` and the drawing both derive from those two constants, in client coordinates. When the window is maximized, the window rect overhangs the monitor by the invisible resize border, but the client area starts exactly at the screen edge.
- **Hover**: detected with `GetCursorPos` + `ScreenToClient` each frame, because over those buttons Windows reports non-client areas and stops sending the client mouse-move messages GLFW's cursor position comes from.
- **Title**: `Window` now remembers the title it last set (`getTitle()`, a marked vanilla edit), because GLFW offers no portable getter.
- **Unchanged**: native edges still resize, and other presentation modes (and the mode selector) get the original frame back. Other operating systems keep their normal decorations.
- **Corners and the native frame**: rounded corners come from DWM (`DWMWA_WINDOW_CORNER_PREFERENCE`; Windows 11 rounds them, Windows 10 ignores the attribute and stays square), never from a window region. `WM_NCPAINT` goes to `DefWindowProc` and `WM_NCACTIVATE` goes with `lParam = -1`, which still stops a caption from being painted over ours. An earlier version swallowed both and also set a rounded `SetWindowRgn`. Windows then switched DWM's frame rendering off for the window, so when the native frame came back (SigmaModern → Modes) it was drawn as the Windows 7 "Basic" frame. Bisected with `-Dsigma.debug.frameDwmState=true`, which logs `DWMWA_NCRENDERING_ENABLED` whenever it changes: it turned off at install when those messages were swallowed, and stayed on when they were passed through.

## Worlds, servers and settings

Three more screens are presented the SigmaModern way, with the same painted-night backdrop as the main menu (blurred, with light snow in front; over a world - the pause menu's route - it blurs the world instead):

- **Singleplayer** (`ModernWorldsScreen`): the saved worlds as glass rows on the left; on wide windows a detail card on the right with the selected world's icon, name, mode, cheats, last played, version, difficulty and any warning, and **Play** as the page's one lit action beside Edit / Re-create / Delete. Below about 700 GUI px the detail card goes away and the actions become a small glass shelf under the list. A world with no icon of its own gets a painted mountain instead of vanilla's grey square.
- **Multiplayer** (`ModernServersScreen`): the same two cards. Rows show a name, the (coloured) MOTD, the player count and latency bars that pulse while pinging; the detail card adds status, MOTD, players, version, the ViaFabricPlus forced version if any, and the player sample. Direct connect / add / refresh sit in the header. The ViaFabricPlus target-protocol picker is a version chip there, honouring the "Off" orientation setting. LAN games appear under a "scanning" divider and get their own detail card.
- **Settings** (`ModernOptionsScreen`): the eight option categories as glass tiles with their own glyphs (they arrive one after another), under the field-of-view slider and the Online / World Options shortcut; telemetry and credits in a quiet footer beside Done.

None of these reimplement vanilla. The screens are the vanilla classes underneath - `ModernServersScreen` extends `JoinMultiplayerScreen` and `ModernOptionsScreen` extends `OptionsScreen`, and `ModernWorldsScreen` hosts vanilla's `WorldSelectionList` - so loading, filtering, selection, double-click and Enter to play, Shift+arrow reordering, pinging, LAN discovery, the add/edit/delete/direct-connect flows, Sodium's video screen, ViaFabricPlus's join handling, world backup/upgrade confirmations and narration are all the originals. Only the layout and drawing are new; every action is the vanilla entry's own method, and every sub-screen returns to the Modern page.

- **Routing**: `Gui.setScreen` calls `ModernScreens.route`, which swaps the *exact* vanilla classes (`SelectWorldScreen`, `JoinMultiplayerScreen`, `OptionsScreen`) when the mode is SigmaModern. So every route in - the Modern main menu, the pause menu, the multiplayer safety notice, a disconnect screen's "back", the list's own refresh - lands on the Modern version with no one-frame vanilla flash. Subclasses pass through, so the Modern screens themselves are never swapped again.
- **Row drawing** is `ModernRows`, called from marked hooks in `WorldSelectionList.WorldListEntry` and `ServerSelectionList` (`OnlineServerEntry`, the LAN header and LAN entries). The row keeps vanilla's click geometry: a click on the 32x32 icon plays/joins, and for servers its left quarters reorder - so the icon shows a play glyph and up/down chevrons on hover. `OnlineServerEntry` now computes the ViaFabricPlus-dependent values (MOTD or address, icon or missing-icon, status text) once, before choosing between the vanilla and Modern drawing; see the note under `core/gui` in `VFP_AUDIT.md`.
- **A resize or a return from a sub-screen** rebuilds the widgets around the existing list and model (`repositionElements`), rather than re-running `init()`, which would reload the server list and start a second LAN detector.
- **Vanilla widgets and pages** the hubs hand off to are reskinned by `ModernSkin` through small marked hooks, so Video / Sound / Controls / Create World / Add Server and the rest read as part of the client: buttons, sliders, edit boxes, checkboxes, list selection and scrollbars, menu tab bars, and the panorama and dirt backgrounds (the painted night, blurred, replaces them). Vanilla keeps its layout, its own font (its widths are laid out for it) and all behaviour; the pause menu picks the buttons up for free. Sodium's own video-settings widgets are untouched.
- **Caption strip**: widgets that vanilla places at the top of a screen (Create World's tab bar) stay clickable, and the caption title now yields to the first one it meets, cutting itself short with an ellipsis. ViaFabricPlus's top-aligned button sits below the strip (`ModernWindowFrame.reservedTop()`).
- **Forced blur**: any screen implementing `ModernBlurredBackdrop` (the ClickGUI and these three) gets the maximum blur radius regardless of the menu-background-blurriness slider.

## Version picker (ViaFabricPlus)

`ModernProtocolScreen` replaces both of ViaFabricPlus's version lists: the global target (`ProtocolSelectionScreen`, from the multiplayer page's version chip, Direct Connect or VFP's API) and the per-server forced version (`PerServerVersionScreen`, from Add/Edit Server's "set version"). `ModernScreens.route` swaps both exact classes, so every existing entry point lands here. Back behaves like `VFPScreen.onClose`.

- **Eras, each with its block**, drawn in isometric from the game's own block textures (`ModernBlocks`, so resource packs show through):
  - Modern (grass block): 1.17 onward.
  - Middle (dirt path, which the Combat Update itself introduced): 1.9 – 1.16.5.
  - Legacy (cobblestone, the game's first block): 1.8 and older, with Release / Beta / Alpha / Classic dividers.
  - Bedrock (bedrock).
  - Auto Detect (observer) is pinned on top.
- **Tabs** jump to each era and follow the scroll. A search pill filters by name, included versions or note.
- **Notes**: versions that mark something carry a one-line note, in Chinese when the game language is Chinese (`ModernVersions`). The notes are keyed by the Via constants, not display names, and were only written where the fact is certain.
- **Hero card**: the left card shows the version under a resting pointer (or the arrow-key focus), else the current one. It gives the era, edition, protocol number (hidden for special versions, whose numbers mean nothing), the note, the included versions, and a Legacy → Middle → Modern timeline with the version's place marked. Choosing a version sets off a small burst of ice shards.
- **Nothing is applied early.** Hover and arrow keys only move the preview; a click or Enter applies, because every change fires VFP's reload listeners (collision shapes, font cache, recipes, sometimes sounds). The global target stays locked while connected, as in VFP's own list, and the card says so.
- **Built from the live registry**, which ViaFabricPlus finishes filling on a background thread (Auto Detect and the Bedrock name arrive last), and rebuilt if it grows. Special versions are never compared by protocol number: they take the era of the release above them. `c0.30 CPE` is placed under Classic explicitly.
- **Header**: VFP's own settings, server lists (disabled while connected) and issue reporter, which all return here. The multiplayer page's version chip now wears the target era's block.
- **Narrow windows** get a one-line version strip instead of the card.

## Typography

All SigmaModern text uses **Anthropic Serif** through a dedicated `ModernFontRenderer`, in three static cuts made with fontTools' `instancer` from the variable web fonts (axes `wght` 300–800 and `opsz` 16–48):

- `anthropic_serif_text.ttf` - weight 400, optical size 16: the default for every UI string (`ModernTypography.Face.TEXT`).
- `anthropic_serif_display.ttf` - weight 300, optical size 48: only for text drawn several times larger than normal, i.e. the wordmark and the clock (`Face.DISPLAY`).
- `anthropic_serif_display_italic.ttf` - the italic at the same settings, for *Modern* and the tagline (`Face.DISPLAY_ITALIC`).

Anthropic Serif and Anthropic Sans share their vertical metrics exactly (cap height 0.72em, x-height 0.54em, the same ascent), so the renderer's 11px size / 9px baseline and every fixed y offset tuned for the Sans carried over unchanged. Neither family has Greek, which is why the Σ mark is a vector path (`ModernIcons.Icon.SIGMA`) rather than a glyph.

`ModernFontRenderer`'s constructor throws rather than silently falling back if a bundled face fails to load, so any SigmaModern text on screen means the bundled font loaded. Its texture ids share one static counter across the three faces. Per-instance counters once handed two renderers the same id, so each overwrote the other's glyph runs and words appeared in each other's places.

Skija 0.143.17 shapes text and rasterizes grayscale coverage; its font manager supplies system-font fallback for missing glyphs (e.g. Chinese). Text is rasterized at twice the actual device size (including GUI scale and local transforms, capped for very large text), then drawn through linear-filtered texture quads that preserve coverage alpha, bypassing Minecraft's font atlas and text shader alpha cutoff. Rendered runs are cached with a 32 MiB / 256-entry target per face, retaining the two most recent extraction frames during eviction. Individual textures are limited to 4096 × 2048. The six headless `ModernFontRendererTest` cases (fractional edge coverage, transparent padding, title resolution, Unicode clipping, Chinese fallback, texture size limits, rounded-mask seams) pass on the Serif default.

Sources - both referenced by anthropic.com's own brand stylesheet (`ant-brand.shared.*.min.css`), the same place the Sans came from:
- https://cdn.prod.website-files.com/67ce28cfec624e2b733f8a52/69971a1551eb6cda0d656e8a_AnthropicSerif-Roman-Web.woff2
- https://cdn.prod.website-files.com/67ce28cfec624e2b733f8a52/69971a15a9fb8c1107a3570e_AnthropicSerif-Italic-Web.woff2

The fonts carry "Copyright 2025-2026 Anthropic PBC" and no license-description field; no open-source license is asserted for these assets. The earlier `anthropic_sans_regular.ttf` (from `…_AnthropicSans-Roman-Web.woff2`) and its `anthropic_sans.json` provider are left in place but no longer used by Modern code. The JSON points at that TTF, so they have to be kept or removed together.

## Shapes, glass and glow

`ModernShapeRenderer` draws Skia antialiased rounded-rectangle masks as nine-slices, cached by radius and GUI scale rather than by full dimensions or color. `ModernStyle.glassCard`/`darkGlass` draw the frosted panels. Each has a rounded drop shadow (`ModernStyle.dropShadow`, expanding rounded rings); `GuiVisuals.softShadow`'s square rings showed as a boxy halo on light backgrounds. On top of the shadow comes a translucent tinted fill and a top highlight sheen, over whatever the screen blurred this frame. `ModernClickGuiScreen` forces vanilla's blur to its maximum radius while open (a small hook in `GameRenderer.extractOptions`), rather than leaving it to the user's accessibility "menu background blurriness" slider.

`blurBeforeThisStratum()` blurs *earlier* GUI strata only. Anything that should be blurred must end its stratum (`nextStratum()`) before the blur is requested, as the ClickGUI does after painting the scene.

Glow/bloom (toggle halos, status dots, the hotbar's selected cell, the main menu's hover bands) is drawn as expanding `rounded()` passes on the ordinary textured pipeline (`ModernStyle.halo`), never `GuiVisuals.softGlow`. Inside an active GUI scissor, `softGlow`'s additive-highlight pipeline silently discarded the shape drawn right after it. `softGlow` itself is left in place but unused.

`ModernSkiaRaster.upload` whitens RGB and is for tint-only coverage masks. `uploadColor` keeps painted colors, and bleeds each column's nearest solid color into near-transparent pixels so straight-alpha linear filtering doesn't draw dark fringes around silhouettes.

## In-game HUD

`ModernHud` draws SigmaModern's always-on gameplay overlay: the **ArrayList** module's list of switched-on modules (top right by default, see below), the **PotionStatus** module's status effects (bottom right), a WASD keystroke display (on the left, under the TabGUI) and the music island (top center, hooked from `Hud.extractRenderState`'s existing POST client-overlay point). It also reskins the vanilla hotbar as rounded glass cells with a glowing selection highlight, via a small branch inside `Hud.extractItemHotbar`; the nine item slots keep their exact vanilla coordinates. All of it is gated on `ClientMode.SIGMA_MODERN` and only draws with no screen open.

In a world, the SigmaModern mark sits in the top-left corner (`ModernHud.renderBrand`, drawn from `Gui` after screens, so it stays over in-game menus and through F1): the main menu's lockup in miniature - the faceted Σ with its soft glow, "Sigma" in the display serif and "Modern" in ice-blue italic on the same baseline - on a 22 px pill of the dynamic island's own glass in its default ice colours, so the two read as one set along the top of the screen and the mark stays legible over a bright sky or snow. The TabGUI and a top-left ArrayList start below it (`BRAND_BOTTOM`).

The left side and F3 follow the old client (`juzibujiji/SigmaClient`'s `EventRender2DOffset`, `ActiveMods` and `KeyStrokes`). Down the left side, below the brand, elements stack: each starts where the one above it ended (`ModernHud.leftStack()`/`stack()`) - the TabGUI, then the WASD keys, then a top-left ArrayList. The keys used to sit in the bottom-left corner, where the chat covered them (and ModernChat lifted its panel 62 px to clear them); now the chat sits where vanilla's does. A top-right ArrayList starts at `ModernHud.rightStack()`: 10 px down, or with PotionStatus off, below vanilla's effect icons (`vanillaEffectsBottom`: a 24 px row for good effects, one under it for bad ones, 15 px lower in a demo world). While F3's text is up, the left stack hides (as the old TabGUI and KeyStrokes did), the ArrayList starts below F3's right column (as the old ActiveMods did) and the brand slides to the top centre, under the island (as the old watermark did). How far each F3 column reaches comes from a Sigma hook in `DebugScreenOverlay.extractLines` (its last drawn line, 9 px apart from y = 2) rather than from a fixed number, so it follows F3's changing line count; entries pinned to show without F3 count too. F3 draws after the HUD, so the HUD uses the previous frame's figure, and the list and the brand ease to their new places.

## ArrayList

The **ArrayList** module (Interface category) is the list of switched-on modules that `ModernHud` used to draw unconditionally. The module holds the switch and the settings and decides which modules are listed and in what order (`ModuleArrayList.listed`); `gui.modern.ModernArrayList` draws it, asking `Modules.enabled` every frame, so switching the module off hides the list. It is **on by default** (`Module.isEnabledByDefault`), as PotionStatus is: `ModuleConfig.read` switches a module the config has no usable `enabled` for to its default, so a config written before the module existed still shows the list. The list never names itself. Switched on untouched, it draws what the old list did: every other module that is on, by name, 10 px from the top-right corner, 11 px apart, with a text shadow. Its settings:

- **Position** (`TOP_RIGHT`, `TOP_LEFT`, `BOTTOM_RIGHT`): the corner it hangs from. Bottom-left isn't offered, because the chat is there. At the top right, while F3's text is up, the list starts below F3's right column. At the bottom, the first line sits nearest the edge, so `LENGTH` still steps in from the corner.
- **Sort** (`ALPHABETICAL` / `LENGTH`): by name (ignoring case), or widest line first (suffix included).
- **Suffix** (default off): after the name, in a dimmer color, the module's first choice setting's value, worded for reading (`Speed Legit Hop`, `Fullbright Night Vision`).
- **Hide Visuals** (default off): leaves out Render and Interface modules.
- **Font Size** (8–16 px, default 11) and **Spacing** (0–6 px extra between lines, default 0).
- **Background** (0–1, default 0): dark glass behind each line, reaching 3 px past the text. At 0 nothing is drawn.
- **Accent Bar** (default off): a 2 px bar in the line's color on the list's outer edge.
- **Color Mode** (`STATIC`, `WAVE`, `RAINBOW`) and **Color** (default `ModernStyle.TEXT`, hidden under `RAINBOW`): `WAVE` runs a brightness wave down the list, and `RAINBOW` cycles pastel hues down it. The line's place in the list drives both, so a line keeps its color as it moves.
- **Text Shadow** (default on).
- **Animations** (default on): a switched-on module slides in from the screen edge. A switched-off one slides out and fades in its old slot while the lines around it ease into their new places. After a gap in drawing (a screen was open) the list snaps into place instead of replaying what changed meanwhile.

## PotionStatus

The **PotionStatus** module (Interface category, **on by default**, as vanilla's icons always show) draws the player's status effects on SigmaModern's HUD in place of vanilla's icons, stacked up from the bottom-right corner: a Sigma hook at the top of `Hud.extractEffects` returns while it is on and the client is in SigmaModern (`ModernHud.replacesEffectIcons`), and `gui.modern.ModernPotionStatus` draws them in `ModernHud.render` right after the ArrayList. The stack's foot sits 10 px above the bottom edge, or 6 px above an ArrayList hanging from the bottom-right corner (`ModernArrayList.bottomRightTop`), so the effects stand on the list; it rises no higher than 6 px below a top-right list (`topRightBottom`) or F3's right column. The list records how far it reached as it draws, so these are the same frame's. The effects are in reading order from the top of the stack down to its foot, and the stack rises and sinks smoothly as effects come and go. Outside SigmaModern, and with the module off, vanilla draws its icons as before. Like the rest of the HUD it only draws with no screen open; the inventory shows effects itself.

**Layout** (`LIST` / `INLINE`, default `LIST`) picks how each effect looks:

- `LIST`: a dark-glass card per effect, 30 px tall and as wide as the widest name and time (at least 128 px), all the same width so the stack's edges line up, 4 px apart: the icon on a rounded 20 px tile tinted with the effect's colour, the name and level with the time at the far end, and the bar under them.
- `INLINE`: lines in the ArrayList's own style - its text size, line spacing, background and shadow (its defaults while the list is off) - with the name, the time in a dimmer color and the icon at the screen edge, so the icons stand in a column and the effects read as part of the list; the icons get a shadow like the text's, since no glass is behind them.

An earlier `COMPACT` layout (icon tiles side by side, six to a row) was dropped as vanilla's grid in new colours; a config that still says `COMPACT` keeps `LIST`. When there isn't room for every effect between the corner and whatever is above: `LIST` cards turn slim first (20 px, a 14 px tile, 2 px bar; back to full only with 8 px to spare, so a list easing across the edge doesn't flip them), and when even that doesn't fit, in either layout the effects with the most time left (endless ones first) fold into a last "+N more" entry, the rest keeping the sort's order (`keepSoonest`).

`PotionStatus` holds the settings and decides which effects are shown and in what order (`listed`, over a plain `Entry` record so it is tested without a game): effects vanilla gives no icon (`show_icon: false`, e.g. `/effect ... true`) are left out, as vanilla leaves them out. Its settings:

- **Sort** (`KIND`, `DURATION`, `NAME`): good effects first, then neutral, then bad, as vanilla's two rows, and soonest to run out first within each; or soonest first overall (endless ones last); or by name.
- **Show Level** (default on): the level after the name in Roman numerals (Speed II), none for level I, plain digits past X.
- **Show Time** (default on): `MobEffectUtil.formatDuration`, as the inventory shows it (∞ for endless effects). In the last ten seconds it turns amber.
- **Duration Bar** (default on, `LIST`): a 3 px bar under the name, in the icon's color, that runs down with the effect (full and dimmed for an endless one); off, the name and time sit in the middle of the card. The client is never told a potion's full length, so the bar measures from the longest the effect has had since it started or was last topped up (another potion, a beacon pulse).
- **Colored Icons** (default on): each icon in its effect's color, mixed toward white until it is bright enough to read on dark glass (`ModernPotionStatus.iconColor`), so blindness's near-black and darkness's grey still show while orange stays orange. Off, the icons are white.
- **Background** (0–1, default 0.6, `LIST`): each card's dark glass; at 0 none, and the text gets a shadow. `INLINE` uses the ArrayList's background instead.
- **Blink Expiring** (default on): the icon pulses in the effect's last ten seconds, quicker and deeper as it runs out, as vanilla's icons blink, but never fades out entirely (`PotionStatus.blink`).
- **Hide Ambient** (default off): leaves out effects from a beacon or a conduit.

Effects slide in from the screen edge when they start and fade in their slot when they end, while the others ease into place, as the ArrayList's lines do.

The icons are SVGs drawn for the client, one per effect in `MobEffects`, at `assets/minecraft/sigma/icons/effect/<id>.svg`, on the category icons' 24 px grid (white 2 px round strokes, tinted when drawn): a sword for strength, a snail for slowness, a pickaxe with a plus or a downward arrow for haste and mining fatigue, hearts for the healing effects (with a plus inside for instant health, a plus beside for regeneration, an upward arrow for health boost, a heart in a heart for absorption, a broken one for instant damage), a skull for wither, a ghost for invisibility, a cobweb for weaving, and so on. `ModernSvg.effectIcon` picks the file by the effect's registry path and falls back to `generic.svg`, a flask, for an effect from outside `minecraft` or without a file. `ModernEffectIconsTest` reads the effect ids off `MobEffects.java`, so an effect added in an update without an icon fails the build; it also checks that every icon is a line drawing inside its box, and with `-Dsigma.test.effectSheet=<file.png>` it writes all of them on one sheet to look over.

## TabGUI

The **TabGUI** module (Interface category, off by default) is Sigma's keyboard menu: the module categories on a dark glass panel in the top-left corner, driven with the arrow keys in game. Up/Down pick a category (held, they repeat), Right or Enter opens its modules on a second panel beside the highlighted row, Up/Down pick a module, Right or Enter switches it (never on key repeat), and Left goes back. Only categories with a module in them are offered, and the TabGUI doesn't offer itself. A category row shows a lit dot while anything in it is on; a module row shows a status dot (lit while on) and, under **Keybinds**, its key. The highlight is the hotbar's selected-slot glow; it glides between rows and the module panel slides open under **Animations**. **Background** (0–1, default 0.6) sets the glass; below 0.35 the text gets a shadow instead.

`TabGui` holds the menu itself - which categories and modules, where the selection is, what each key does (`press`) - and `gui.modern.ModernTabGui` draws it. A key only moves the menu while a presentation has drawn it in the last 250 ms (`markShown`), so outside SigmaModern, or while the F3 debug text (which starts in the same corner) hides it, the arrows do nothing to it. A key that a vanilla key mapping or a module keybind already uses is left to them, and the menu never cancels a key, so someone who walks with the arrow keys keeps walking. It is the first element of the left stack under the brand; the WASD keys and a top-left ArrayList follow below it.

## Chat

The **ModernChat** module (Interface category, off by default) restyles the chat in Anthropic Serif, on the same dark ice glass as the rest of Modern. It isn't tied to the SigmaModern presentation: the module holds the switch and the numbers, and `gui.modern.ModernChat` does the drawing from hooks that ask `Modules.enabled` for it. Switched off, the next frame is vanilla's chat again, re-wrapped in vanilla's font. Its settings:

- **Font Size** (8–16 px, default 11, Modern's own size): text, line pitch (12 px at 11), wrapping, and the input bar's height all follow it. The command suggestion list stays at 11 px, because its rows keep vanilla's fixed 12 px pitch and click math. Its x still follows the scaled input.
- **Background** (0–1, default 0.5): how solid the panel's glass is. It replaces vanilla's text-background opacity for this chat.
- **Corner Radius** (0–12, default 10): rounds every shape up to its designed radius (panel 10, bar a pill, cards 7), so the default looks as designed and 0 is square.
- **Animations** (default on) and **Animation Speed** (0.5–2): cover the unfurl and fold, the panel's growth and shrinking, slide-in and the gliding caret. Off, everything snaps into place.
- **Text Shadow** (default off): for a see-through background.

What it draws:

- **The input bar**: a rounded pill, full width at the bottom (vanilla's strip covers the hotbar too). Opening the chat unfurls it from a circle at its left end over 0.32 s (ease-out). It rises 5 px, and a faint ice halo comes up with it. The text fades in once the bar has room. Closing folds it back over 0.22 s. The HUD keeps drawing that collapse after the screen is gone, so closing is animated as well. The bar's left glyph is a speech bubble for messages and turns into a `›` prompt mark once the line starts with `/`. An empty line shows a muted italic placeholder. Once the line reaches 70 % of the server's limit, a `123/256` counter appears. It goes red at the limit. ViaFabricPlus lowers that limit on old servers. The caret glides between positions. It stays solid while you type and pulses softly when idle. Selection is an ice-blue rounded band. Vanilla's suggested completion shows as muted text past the caret.
- **The message panel**: one rounded glass card, not a black strip per line. Unfocused, it holds only the lines that are still fading, and sits where vanilla's does. The card grows and shrinks smoothly as lines arrive and fade, and it fades with its newest line. When the chat opens, the card grows upward to a full page while the bar unfurls. Its bottom edge also settles down onto the bar. In survival it stops above health and hunger, like vanilla's chat; in bed it stops above the "leave bed" button. Lines above the rising top edge fade in as the card reaches them, and new lines slide up from the bottom edge. The scrollbar is a hairline at the right edge. It turns ice-glow while newer messages are waiting below. The chat-opacity, text-background-opacity, width, height, scale and line-spacing options all still apply. The module's Background setting scales the glass.
- **Command suggestions and usage hints**: glass cards above the bar. The selected row gets the same ice pill and accent bar as the rest of Modern.

How it stays vanilla underneath: vanilla still decides everything - which lines exist, wrapping, scrolling and paging, history, drafts, command parsing, click and hover events. It just lays out through `ModernChatFont`. That is a vanilla `Font` whose default-font advances come from the chat's Skia face, so wrapping, the input's scroll/caret/click-to-position and the suggestion list's x and width are all measured in the face that draws them. That face shapes without kerning or ligatures (`ModernFontRenderer.PLAIN`). Runs are also split where Anthropic Serif hands over to a system font (a space next to Chinese shapes differently inside a mixed run). Together, these make a drawn run exactly as wide as its characters' advances summed; `ModernFontRendererTest` checks this, including the synthesized bold and italic. Drawing and clicking go through one layout (`ModernChat.layout`, reached from `ChatComponent`'s private `extractRenderState`). `ChatScreen` hit-tests with `ModernChat.ClickFinder` instead of vanilla's glyph-bitmap `ClickableStyleFinder`, and hovered styles reach vanilla's tooltip and cursor handling through `GuiGraphicsExtractor.hoveredTextStyle`. Some text isn't drawn by Skia: resource-pack glyphs in the private use areas, other fonts (`alt`, player-head sprites) and obfuscated text. Those keep vanilla's advance and are drawn by vanilla on the serif baseline. Tooltips and the IME's composition overlay stay in vanilla's font. Lines are 12 px apart (before the line-spacing option), which leaves room for the serif's descenders. The chat re-wraps when the mode switches.

Checked in a quick-play world at 1280×800 and 854×480: open, mid-open (frames 1–3), closing, unfocused, and an overfull page showing its scrollbar (at the newest end; a scrolled-back position and chat scale ≠ 1 weren't captured). As a module: switched off, the chat is vanilla's; on at 14 px with `/t`, the taller bar, line pitch, wrap and suggestion anchor were checked, and with real input the wrapped link's tooltip and click-through still hit. Also: syntax-highlighted commands with the usage card, the live suggestion list for `/t`, bold, colors, italics, an underlined link and Chinese fallback. With real input, hovering the link showed its tooltip, and clicking it opened vanilla's link confirmation with the right URL.

## Music player

A streaming player for NetEase Cloud Music, with word-timed lyrics from NetEase or QQ Music, laid out after the reference's music view and island. `-Dsigma.debug.musicOffline=true` swaps in the old offline preview (demo list, silent backend, no network).

- **Model** (`com.mentalfrostbyte.jello.music`, no rendering or game code):
  - `MusicPlayer` owns the queue and transport. Choosing a track, next and previous all start playback. A finished track moves on and the queue wraps. "Previous" restarts the current track once it has played for 3 s.
  - The volume is saved under `"music"` in the Sigma config; a malformed saved value is ignored.
  - Tracks come from a `MusicSource`: a `ListSource` (the NetEase hot chart, a search's results) or, offline, `DemoMusicSource` (the reference's three "Jello sessions" pieces with its album cover, `textures/gui/sigma/modern/music/jello_sessions.png`, cut from the HTML at 512 px).
  - They play through a `MusicBackend`: `StreamingBackend` online, `SilentBackend` offline (it only keeps wall-clock time).
  - An unplayable track is skipped, up to 3 in a row and only while playing; after that the player pauses and keeps the reason as `problem()`, which the window shows ("not available (copyright or VIP)", "network error", ...).
  - `MusicPlayerTest` covers the rules (9 cases).
- **NetEase** (`music.netease`, adapted from SigmaClient's crawler): `NeteaseCrypto` (weapi and eapi encryption), `NeteaseSession` (a device id in `sigma5/netease_device.json`; reads a SigmaClient-format `sigma5/netease_cookie.dat` if one is there, keeping only the login cookies; cookies are never logged) and `NeteaseApi`:
  - Search is eapi `/api/cloudsearch/pc` (the weapi web search answers anonymous requests with code 50000005); the hot chart is playlist 3778678.
  - Streams: eapi at exhigh (320k MP3), then standard, then weapi, then the outer redirect. Anonymous access plays free songs in full; VIP songs (fee 1) only give a 30 s preview, which the window marks as a preview clip and ends at its advertised length. Only MP3 is accepted.
  - Tracks are tagged `VIP` / `PAID`; covers are `https` URLs at 256 px.
- **QR login** (`NeteaseAccount`): the desktop client's flow, as SigmaClient did it - eapi `/api/login/qrcode/unikey` and `/api/login/qrcode/client/login`, both with `type=3` and no made-up `NMTID` (the combination NetEase doesn't answer with its 8821 security refusal). Poll replies: 801 waiting, 802 scanned (with the scanner's name and avatar), 803 confirmed (the reply's `cookie` field plus its `Set-Cookie` headers carry the login), 800 expired. Polls run every 2 s on a login thread, for at most 5 minutes; each attempt has an id, so a refreshed code or a sign-out stops the one before. The interface reads an immutable `State` and never waits on the network.
  - `NeteaseSession.signIn` keeps only the session cookies (`MUSIC_U`, `__csrf`, `MUSIC_A_T`, `MUSIC_R_T`, `NMTID`; attributes and the rest dropped, one parser shared with loading) and writes `sigma5/netease_cookie.dat` atomically in SigmaClient's format; `signOut` deletes it. No login reply, cookie or cookie-file content is ever logged.
  - Who is signed in comes from `/weapi/w/nuser/account/get`. Only NetEase's explicit "nobody" answer (`{"code":200,"account":null,"profile":null}`, captured anonymously) counts as a lapsed login and drops it, and only for a login loaded from disk: right after a QR login (whose weapi cookie set was never observed before the first real scan) it's shown as "signed in - couldn't read the profile" with a retry instead. A network error or any other reply leaves the saved login alone. The `Sigma/Netease` log says which cookies a login kept (names only) and which way each account check went, for diagnosing a first scan. Membership shows as a generic "VIP" (any `vipType` above 0).
  - After a QR login, a track that was playing as a 30 s preview is loaded again (`MusicPlayer.reloadCurrent`, on the main thread) so it plays in full.
  - QR codes come from ZXing core 3.5.3 (Apache-2.0; the second new dependency in `pom.xml`).
- **`StreamingBackend`**: per loaded track, a download thread fills a `GrowingBuffer` (the whole MP3 stays in memory, so a seek re-reads it without downloading again) and a play thread decodes it with JLayer 1.0.1 (LGPL, the only new dependency in `pom.xml`) into a Java Sound line with a 200 ms buffer. The volume (times Minecraft's master volume) is applied to the samples. The position is counted from frames the line has actually played, so lyrics stay in step with what is heard. Nothing blocks the render thread; every load has a generation id so a late thread from a previous track can't touch the new one. A seek needs a fresh JLayer `Decoder` (its Layer III decoder binds to the first bitstream it sees).
- **Lyrics** (`music.lyrics`, `music.qq`): `LyricsService` looks lyrics up in the background from the chosen **channel**:
  - Mixed (default), best first: NetEase YRC (word-timed), from eapi `/api/song/lyric/v1` only (the old weapi lyric call never returns it); otherwise the NetEase LRC (line-timed) at once, replaced if QQ Music has a QRC (word-timed) for the same song. `QQMusicMatcher` accepts a QQ search result on title, artist and duration (score 0.55 or better), and `QQMusicDecoder` decrypts the QRC (the triple-DES variant plus zlib).
  - NetEase: YRC, else LRC, never QQ. QQ: the QRC only.
  - NetEase's YRC comes and goes: the same song had it one hour and not the next (anonymous and signed in alike), and many songs never have it. That is why Mixed is the default; the log names the winner per track (`Sigma lyrics: '<title>' - QQ (WORD, MIX)`).
  - The **mode** then decides what is shown: Auto (word by word when word-timed, else line by line), Line (always line by line: word-timed lines lose their word timing), Word (only word-timed lyrics; a track with only line-timed ones shows "no word-timed lyrics"). Changing the channel looks everything up again; changing the mode only changes what is shown. Both are saved in the Sigma config's `"music"` object (`lyricChannel`, `lyricMode`; an unknown value keeps the default), which `MusicPlayer.write` now merges into instead of replacing.
  - The **language** decides what goes with each line: 原文 (nothing), 译文 (its Chinese translation under it; the default - only songs not in Chinese have one), 音译 (its romanization under it) or 仅译文 (the translation instead of the line, lit whole). Translations and romanizations come from the lyrics' own service - NetEase `tlyric` / `romalrc` (LRC, the same time tags as `lrc`), QQ `contentts` (plain LRC, timed like the QRC's lines) / `contentroma` (encrypted QRC) - and `LyricsParser.attach` hangs each on the line starting nearest to it within 1.2 s (`//` placeholders dropped). In the mixed channel, NetEase's fill the lines a QQ QRC left without one. Saved as `lyricLanguage`. The panel draws the extra line smaller under each line (brighter while it's sung); the island, the mini player and the compact subtitle show only the line itself (the translation in 仅译文).
  - NetEase's own data sometimes drops a space between English words in YRC ("I'm" then "going"); it is shown as it comes, since YRC also splits single words into timed syllables and a space can't safely be guessed.
  - An instrumental is marked as such. `LyricsParser` reads all three formats (JSON credit lines, offsets, multiple time tags); `LyricsParserTest`, `QQMusicMatcherTest` and `NeteaseCryptoTest` cover them against captured fixtures.
- **Wiring**: `Client` owns the player, registers it on the event bus (a tick checks for a finished track, so it keeps going in menus and in game), reads and writes its config with the modules, and unregisters it on rollback and shutdown.
- **The music window** (`ModernMusicDrawer` around `ModernMusicView`, 282 px wide) is its own window, not part of the ClickGUI card.
  - Hidden past the right edge of the screen, with only a small glass tab showing: a chevron, an equalizer that moves while music plays, and a grip. Hovering the tab shows "Drag out the music player".
  - It has to be pulled out by hand. Grab the tab and drag left (or, once it's out, grab the tab or the window's title bar). On release it springs fully open or back shut; a flick decides by its direction, a slow release by how far out the window is. A click without a drag only nudges it out and back.
  - Whether it's out is remembered across screens. The ClickGUI and the main menu both host it.
  - In the ClickGUI, the card narrows and moves over to make room (down to 300 px wide; past that, on small windows, the window overlaps it). On the main menu the clock steps aside for it.
  - The window draws in its own GUI stratum, and nothing underneath reacts to the pointer while it's over the window.
  - Layout: a "Jello music" title bar across the top (the account, settings and an equalizer); a **category rail** down the left - 播放 (the player), 搜索, 热歌, 新歌, 飙升, 原创 (the NetEase charts), 鸣潮 (the artist, as SigmaClient's player had it) and, signed in, 日推 (daily picks) and 歌单 (one's playlists); it scrolls when there are more entries than fit. The rest is the page the rail (or a title-bar button) points at. `MusicBrowse.CATEGORIES` (the browse model the window and Jello's music panel share) is the list: a category is one line there (a chart or playlist id, an artist id, or a kind).
  - The player page, as in the reference's player column: the album art (album and mood lettered on it); the title and track number; the artist with the stream's state; a draggable timeline (the seek applies on release); the transport; the queue, named after its source; and the volume.
  - Online, the queue starts as the NetEase hot chart, fetched the first time the window is shown ("click to retry" if it fails). Remote covers download in the background (`ModernCovers`, LRU of 40 rasters whose textures are released on eviction); the generated cover stands in until they arrive.
  - Clicking the art turns it over to the lyrics (`ModernLyricsPanel`) on an opaque card of its own, drawn over the cover exactly as drawn (mid-switch the sleeve can still be popped out while playing) and a pixel wider, so no cover shows round or through it: the line being sung sits a little above the middle with a karaoke sweep (`ModernLyricSweep`: word by word for YRC/QRC, the whole line for LRC or in Line mode), neighbouring lines fade out, and a corner label names the source and kind ("QQ 音乐 · 逐词", "网易云 · 逐行"). Without lyrics it says why, naming a strict channel that came up empty ("QQ 音乐暂无此歌歌词"). When there's no room for the art, the sung line takes the subtitle's place instead.
  - A dotted ring round the play button while buffering; "preview clip" in the subtitle for a VIP preview; the reason in red when a track can't play.
  - Every category but the player opens the browse page (`ModernMusicBrowser`): the list with covers, artist, length and VIP tag, and a strip at the foot with what's playing (its play button and the lyric line; a click on it goes to the player). Picking a song queues that list, named after its category, from the song and plays it. Lists come from `MusicLibrary`'s cache, keyed per chart / playlist / artist and, for daily picks and playlists, per sign-in; a failed one says "click to retry" and a click asks for exactly that list again (for playlists, the profile too). Artist songs arrive in NetEase's older format without covers and are resolved through `song/detail`, like playlists. 歌单 lists the account's playlists (its own and saved ones; `user/playlist` with the profile's user id); one opens with its first 200 songs, and the label ("‹ name") goes back. Signing out while on 日推 or 歌单 falls back to 热歌.
  - The search category has the field above its results, and an advanced-options button beside it: its row picks the lyrics **channel** (混合 / QQ / 网易云). Only the most recent search's results are ever shown.
  - The gear opens the settings page (`ModernMusicSettings`): the lyrics **mode** (自动 / 逐行 / 逐词) and **language** (原文 / 译文 / 音译 / 仅译文), each with what it does, which channel is in use (and where to change it), and what the current track's lyrics are ("QQ 音乐 · 逐词"), so a choice can be seen working. Both choices are saved at once.
  - The person beside the magnifier opens the account page (`ModernMusicAccount`), lit with a dot when signed in. Signed out, it fetches a code as soon as it's shown and draws it as dark modules on an opaque white card with a four-module quiet zone, at whole GUI pixels per module (error correction L, for bigger modules); on a window too small for 2 px modules it says to make the window taller instead of drawing an unreadable code. Under it: waiting / scanned (the code steps back behind a check and the scanner's name) / expired, refused or failed (click the card for a new code), and two lines on what signing in does. Signed in: the avatar, the nickname, VIP or not, and "Sign out". Escape or the rail return to the player.
  - While the search field has focus it takes every key and character, wherever the pointer is: Space, Right Shift and `/` type instead of reaching the player or the ClickGUI, Enter searches, Ctrl+V pastes, Escape lets go of the field (a second Escape on the window goes back to the player). A click anywhere else, the window shutting, or the host screen closing also releases it. Buttons in the title bar are clicks, not handles for dragging the window.
  - The field reports focus to Minecraft the way a vanilla `EditBox` does (`onTextInputFocusChange`); without that, 26.2's `TextInputManager` switches the system IME off every tick, so Chinese couldn't be typed. The IME's composition shows in vanilla's pre-edit overlay under the field, which also places the candidate window. The global ClickGUI hotkey (`ClickGuiHandler`, which runs ahead of any screen) passes Right Shift by while a screen reports typing through `TextEntryScreen`, so it types a capital instead of closing the ClickGUI or opening it over the main menu.
  - With the pointer on the window: Space plays and pauses, the arrow keys seek and change the volume, and the wheel changes the volume (or scrolls a long queue).
  - Short on height it keeps the art and gives up queue rows, down to one; on a small window it drops the art and puts the transport beside the title, with the queue below.
- **Effects** (`MusicEffects` settings; the settings page's 动效 tab; all on by default, particles soft; saved in the shared `"music"` config object):
  - **Environment audio** (`MusicEnvironmentListener` → immutable `MusicEnvironment` → `MusicEffects.AudioTarget` → `EnvironmentAudioProcessor`): only the game thread reads the world. The decoding thread filters, adds a light room tail, analyses, then applies player/master volume. Each playback session owns its filter and delay buffers; seeking clears their history. Effects are local, retain the audio line's 200 ms latency, and neither add ambience recordings nor change pitch/speed. All disabled, or environment strength zero, smoothly settles to untouched PCM.
  - **Liquids**: eye-in-fluid is checked every tick, so wading stays dry. Water retains the 650 Hz low-pass, 30% level dip and 0.18 s glide; lava has its own 400 Hz/40% preset and 0.8 s glide. An enabled liquid effect fades out weather and room processing. `fxUnderwater` remains the water key; `fxLava` is independent. Loading an old config without `fxLava` inherits an explicit old `fxUnderwater` choice, preserving opt-outs.
  - **Space reverb** (`fxSpace`): every five ticks, six fixed world-axis collision rays from the eyes sample up to 24 blocks, after checking actual client chunk-cache availability. A roof and at least two side obstructions are needed; their count and average distance estimate enclosure and size. Small rooms have a short tail, larger caves a longer one (0.3–1.2 s, at most 10% wet). Missing chunks, open sky and spaces with no ceiling within range produce no spatial effect. This is a bounded spatial estimate, not a cave classifier. World/player replacement, disconnect and shutdown clear the sampled state.
  - **Weather tone** (`fxWeather`): exposed rain/snow softly lowers the top end (14/10 kHz at full strength), following the rendered weather, including the Weather module and VFP's forced snow. Local precipitation, sky access and the motion-blocking heightmap exclude dry biomes and roofs. Weather and room changes glide over 0.8 s.
  - **Controls**: independent water/lava/space/weather switches and `fxEnvironmentStrength` (0–100%, stored as 0–1; default 100% of the light presets) precede the visual controls. Invalid persisted types/non-finite numbers are ignored and finite out-of-range numbers are clamped. The shared scrolled layout clips drawing and hit testing, including compact windows.
  - **Analysis** (`AudioAnalyzer`): every 1024 samples, a Hann-windowed 2048-point FFT of the filtered samples (before the volume, so visuals move when muted and dull under water), folded into 48 log-spaced bands (50 Hz-15 kHz, highs lifted about 3 dB an octave, levelled against a slowly falling peak) plus a beat test on the 40-160 Hz energy against the last second's average (1.45x, at least 280 ms apart). Snapshots (`Spectrum`, with a beat *counter* so a 60 fps display can't miss or double a beat) go through a fixed ring stamped with track time; the HUD reads the one for the *played* position. Reset on a seek. `SilentBackend` makes one up (a beat every 500 ms) for offline captures.
  - The decoder's clock now adds each MP3 frame's exact length (about 26.12 ms) instead of rounding it down to 26 ms - that had put the position about 0.8 s behind the audio three minutes into a seek, so lyrics ran early after seeking.
  - **Spectrum** (`ModernMusicFx`, drawn first in the HUD pass so the hotbar and hearts sit on top; F1 hides it): bars across the whole bottom edge, quick up and slow down, with caps that drop behind them; a dark foot under the colour keeps them readable over snow or sky. Three dials on the 动效 tab (sliders, saved as `fxSpectrumHeight` / `fxSpectrumIntensity` / `fxSpectrumOpacity`, clamped on load): height (5-40% of the screen, default 18%), intensity (0.5-2.5x, default 1.6x: the bands go through a 1.5 power so loud and quiet stand further apart, then the gain; a beat kicks them all up a little more) and opacity (20-100%, default 85%). The tab scrolls with the wheel when the window is too short for it.
  - **Beat particles**: soft sparks thrown up from the bottom on each beat (soft: a few; strong: a burst, and the bottom edge flares). Frame time is clamped, so returning from a pause or a hitch can't release a burst.
  - **Cover colour** (`ModernCoverColors`): the cover's most vivid hue (a 32x32 sample, weighted by saturation and brightness, 36 hue buckets) becomes a bright accent and a deep version dark enough under white text; grey or pale covers keep the ice colours. Worked out on the CPU on its own thread, from the bytes `ModernCovers` already downloaded, decoded with ImageIO - no GPU readback, no GL call, nothing uploaded off the render thread. Between songs the old colours stay until the new cover's are ready. The island's glass, rim, glow and equalizer, the spectrum and the particles all take it.
- **Island** (`ModernIsland`): a light glass pill showing the cover, the title, "Playing / Paused · source" - or, while a line is being sung, that line with its sweep (the pill then keeps one wider size rather than resizing per line; a finished line stays lit through pauses of up to 2.5 s) - and an equalizer that follows the music's spectrum. A sung line too long for the pill scrolls rather than being cut short with an ellipsis (`ModernLyricScroll`): word-timed, it follows the sweep, holding the sung word about 60% of the way across so the next words show; line-timed (LRC, Line mode, 仅译文), which only says when the line starts and the next one does, it holds the start for up to 1 s, eases across over that slot and rests at the end for up to 0.8 s - never slower than 18 px/s, so a line before a long break doesn't crawl. The sung line's translation row scrolls over the line's time the same way. Where a scrolled row runs past an edge, its last 6 px fade out. The lyric language applies here too: 仅译文 shows the translation; with 译文 or 音译, while the song's lyrics have any, a second, smaller row holds the sung line's translation or romanization. Only a sung line that has one opens it - not the credit lines lyrics start with ("title - artist", "作词 : ..."; a first version opened for any line and left an empty row under those), nor the intro - and once open it stays open while lines keep coming, over untranslated ones and the short pauses between lines (so it doesn't pump); a long break, a pause or the next song closes it. It eases open and shut over about 0.4 s, and the last translation fades out with it.
  - With nothing being sung (the intro, a long break, a song without lyrics) the island shows the track's details instead: the second line reads "artist · 《album》" (the album left out when it's just the song's name; paused: "已暂停 · artist"), and the small row names the writers from the lyrics' credits - "作词 X · 作曲 Y", or "词曲 X" for one writer, longer name lists cut to two "等". `LyricCredits` tells credit lines ("title - artist", "作词 : ..." / QQ "词：..." / "Lyrics by : ...", or any short all-Chinese role) from sung ones; `ModernLyricSweep.now` skips them, so the island, the mini player and the compact subtitle never show a credit as if it were sung. Checked on real lyrics: 起风了 (NetEase), Lemon (QQ, with its "title - artist" line), Blinding Lights, and a Russian song. It eases in whenever the game view comes back. When a module is switched in game (not from an open screen), it grows a second row with the module and its new state for 1.6 s. The reference also expands the island on click into full controls; in game there is no pointer, so no expand affordance is drawn and the controls live in the ClickGUI.
